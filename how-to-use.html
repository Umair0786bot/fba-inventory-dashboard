AGetting data in

Do this once a month, when Ali sends a new LTSF workbook. Everything the app shows comes from here — if this is stale, every number on every tab is stale.

1

Drop the workbook in

Put the new LTSF <Month>.xlsx into:

PD US\LTSF-SOURCE-FILE\

The build picks the newest .xlsx by modified date automatically — you don't rename anything and you don't edit a config. It's currently running on LTSF July (5).xlsx.

2

Build the data file

cd "c:\Users\umair\OneDrive\Documents\PD US"
python build_ltsf_data.py

This reads five sheets — Summary USA, 1 Year Projections of Current, SKU Cash Action Tracker, Rate Card and L30 SV — and writes site\ltsf-data.js.

Check the reconciliation before you go further. The script prints these as it runs. If they don't tie to the workbook, stop — the app will be wrong and it will not tell you. 
SUM Total AIS Charge:    $52,311.06   (sheet grand total ~ $52,311)
SUM Total AIS Units:     45,047       (sheet ~ 45,047)
cash-tracker inputs on:  516 of 517 SKUs
3

Rebuild the page — only if someone changed the app itself

python assemble_index.py
⚠ site\index.html is generated. Never edit it directly — your edits get wiped the next time anyone runs the assembler. The real sources are site\index.base.html plus the eight fragments in _build\.

If you only swapped the workbook, skip this step entirely.

4

Publish

.\deploy.ps1

Needs gh auth login once, the first time. Live about a minute later.

To just look at it locally without publishing, double-click site\index.html — it needs no server.

BUsing it, tab by tab

Six tabs. It opens on LTSF Overview — but your daily work is tab 2.

📊Tab 1 — LTSF Overview · "How bad is it?"

Read-only. Eight cards, thirty seconds, then move on.

The one that matters: Est. LTSF / AIS next month = $52,311. That is the bill Amazon sends on the 15th if nothing changes.

Entering AIS soon is currently 0. Nothing is sitting in the 91–180 day bucket, so no new stock is about to start getting charged. This month's problem is entirely the stock you already have.

Below the cards: charge by age band, units by age, top SKUs and a parent breakdown. Use these to know who to talk to — SLQS alone is $14,359, 27% of the whole bill.

🧮Tab 2 — Decision Engine · "What do we do?"

This is the tab. It is built as four numbered steps — work down them in order.

Step 1 — Where do we stand?

KPI row, same story as the Overview but scoped to whatever filters you've set.

Step 2 — What are our options worth?

A table comparing five plans across the whole book. Read one column: Net recovery — cash collected minus surcharge paid. Biggest number wins. The last column shows each option against doing nothing.

Step 3 — Set the plan

ControlWhat to do with it
Parent / SizeNarrow to one product line
Discount basisThe main lever — Flat % · Ceiling · Floor · ★ Best %
Flat %Only used when basis = Flat. Defaults to 30%
Referral %Amazon's cut. Leave it at 15
Use ★ Best %. It solves the ideal discount for each SKU separately. Flat 30% is only the default because it is the simplest thing to explain in a meeting.

Underneath, a plain-English paragraph rewrites itself as you change the controls. Read that — it is the summary you would say out loud in the huddle.

💵 FBA Liquidations drawer (collapsed): what the stock is worth if you hand it to a liquidator. Recovery % of price — currently 7.5% — is the number worth arguing about; set it to what your own liquidation settlements have actually paid. The chip on the closed drawer gives you the answer without opening it: "7.5% of price → $79,570 net on 45,047 units."

Step 4 — Which SKUs, and what do we do with each?

517 rows, 18 columns. Read the ACTION column — that is the per-SKU recommendation. Right now the book splits:

⏳ HOLD 410 💵 LIQUIDATE 98 🏷️ DISCOUNT 9

  • Essentials only is ticked by default — 18 columns instead of 60+. Untick it only when you need to audit a specific number.
  • Compare all scenarios puts Ceiling / Floor / Best side by side.
  • ⤓ Export (CSV) exports what is on screen, not everything — so the file always matches the table you exported it from.

The optimizer — advanced, collapsed

🧠 Discount optimizer & assumptions, at the bottom of the tab. This solves the exact best percentage per SKU rather than applying a rule to everything.

ControlWhat it does
Cap atFloor is the hard cap — never go past it
Window36 months. Solve to full clearance
Age-forward LTSF ratesON = brackets shift as stock ages ($5.45/cu ft past 271 days). OFF = current rate held flat, which is what the Excel workbook does
⚙ AssumptionsAd rates, coupon clip, elasticity k, grid step
🎯 Elasticity & kCalibrate against measured uplift. Needs ≥14 days of clean data with PPC held constant
Age-forward is the single biggest difference between this app and the Excel brief. Toggle it off and watch the total move — that one switch is most of the gap.
  • Click any row → the "why this number won" modal: waterfall, scenario matrix, and a copy-paste justification paragraph.
  • ⤓ Optimizer CSV — this is the file Ali's Master Tracker consumes.

CThe 5-minute daily routine

  1. Tab 3 — Sales Tracking. Check the tracking window date is recent. If it isn't, re-run Part A before you read anything else.
  2. Tab 3 → Status = 🔴 Behind target. That is today's list.
  3. Tab 2 — Decision Engine. Set Discount basis = ★ Best %, then read the plain-English paragraph.
  4. Tab 2, Step 4. Work the ACTION column, SKU by SKU.
  5. Tab 4 — Command Center. On the wall for the huddle.

Monthly: new workbook → Part A → confirm the two reconciliation lines tie → deploy.

DTwo things the app will not tell you

Both are live right now. Until they're fixed, you have to carry them in your head.

1 · The tracking data is stale, and nothing flags it.

The window is fixed at 2026-07-15 → 07-23. The Sales Tracking tab and every pacing gate keep answering confidently off that window no matter how old it gets. There is no banner, no warning, no greyed-out state. Check the date yourself, every time.

2 · The two panels on the Decision Engine disagree — and nothing says why.

PanelTotal payoutTo liquidate
Main table (Step 4)$632,66398
Optimizer drawer, below it$17,010144

They are answering different questions — the top prices everything at a flat 30% over a lifetime horizon; the optimizer solves per-SKU with age-forward LTSF drag and fee-adjusted exit values. Neither is wrong. But nothing on screen explains the gap, and neither is close to the Excel brief's $575,223. If this goes to management as-is, that is the first question you will get.
